# 跨平台轻量视频播放器 — 设计文档

日期: 2026-05-29
状态: 已确认 (待用户最终评审)

## 1. 目标与约束

构建一个跨平台、高性能、小体积、易上手的桌面视频播放器。

### 核心目标(按用户确认的优先级)

- **跨平台**: Windows + macOS + Linux 桌面三端。
- **小体积**: 最终安装包/可执行文件目标 ~25MB(捆绑裁剪版 FFmpeg,预留余量)。
- **高性能**: 硬件解码优先、秒开启动(< 1s 出画面)、流畅 seek、低内存占用。
- **易上手 + 简洁美观**: 界面克制,核心操作零学习成本。

### 明确的非目标 (YAGNI)

- 不做移动端 (Android/iOS) 和 Web 端。
- 不追求"全格式通吃"(如 VLC)。冷门/老旧格式不在范围内。
- 不做视频编辑、转码、录制功能。
- 不引入数据库;偏好与播放记忆用本地文件存储。
- 不打包任何浏览器内核 (排除 Electron/Tauri-webview 类方案)。

## 2. 技术栈

| 层 | 选型 | 理由 |
|----|------|------|
| 语言 | Rust | 无 GC/无运行时,体积与内存天然占优;内存安全 |
| GUI | egui | 即时模式,逐帧刷新场景契合播放器;纯 Rust;体积小 |
| 渲染 | wgpu | 跨三端统一映射到 Metal/D3D12/Vulkan |
| 解码 | FFmpeg (裁剪版) | 通过 Rust 绑定调用;只编译主流解码器 |
| 硬解 | 系统 API | macOS VideoToolbox / Windows D3D11VA / Linux VAAPI |
| 音频 | cpal | 跨平台音频输出,作为主时钟来源 |
| 存储 | TOML/JSON 文件 | 轻量,无需数据库依赖 |

### FFmpeg 裁剪策略

`--disable-everything` 后选择性 `--enable-decoder` 主流解码器:
- 视频: H.264, H.265/HEVC, VP9, AV1
- 音频: AAC, Opus, MP3, FLAC, Vorbis
- 解封装器: mp4/mov, mkv/webm, 及对应的 parser

关闭所有编码器、滤镜(保留必要的缩放/像素格式转换)、网络协议、冷门格式。
配合 `strip` 去符号、`-Os` 体积优化。目标:FFmpeg 部分压到 ~10-15MB。

## 3. 整体架构

单进程,多线程。UI 线程永不阻塞于解码等重活。

```
┌─────────────────────────────────────────────┐
│            UI 层 (egui + wgpu)                │
│  控制栏 · 播放列表 · 字幕渲染 · 拖拽 · 设置    │
└───────────────┬─────────────────▲───────────┘
        用户指令 │                 │ 状态读取
┌───────────────▼─────────────────┴───────────┐
│          播放控制核心 (player-core)           │
│  状态机 · 播放列表 · 命令队列 · 状态广播       │
└───────────────┬───────────────────────────────┘
                │ 控制解码/渲染管线
   ┌────────────▼───────────┐  ┌──────────────┐
   │ 解封装+解码线程 (media)  │  │ 音视频同步    │
   │ demux→硬解优先→软解回退  │→ │ (sync)        │
   └────────────┬───────────┘  │ 音频主时钟     │
                │ 有界帧队列     └──────────────┘
   ┌────────────▼───────────┐  ┌──────────────┐
   │  视频渲染 (render/wgpu)  │  │ 音频输出      │
   │  纹理上传·色彩转换       │  │ (audio/cpal)  │
   └────────────────────────┘  │ ← 主时钟来源   │
                               └──────────────┘
```

### 关键设计决策

- **解码/渲染独立线程,UI 线程只画界面**: 秒开 + 界面不卡顿的保证。
- **音频主时钟**: 视频帧向音频对齐,丢帧/复帧。音画同步最自然的业界标准。
- **有界帧队列**: 视频只缓存数十帧,绝不整文件读入内存。低内存占用的关键。
- **seek**: 清空队列 → 跳到最近关键帧 → 重新解码。配合独立解码线程实现流畅 seek。

## 4. 组件划分 (Cargo Workspace)

按单一职责、可独立测试原则拆分为多个 crate:

| Crate | 职责 | 依赖 | 可测性 |
|-------|------|------|--------|
| `player-core` | 播放状态机、命令队列、播放列表、状态广播 | 无 GUI/FFmpeg 类型 | 纯逻辑,易单测 |
| `media` | FFmpeg 封装: 解封装、解码、硬解协商、软解回退 | FFmpeg 绑定 | unsafe 收敛于此 |
| `sync` | 音视频同步: 音频主时钟、视频帧调度 | 无 | 纯计算,可单测 |
| `render` | wgpu 视频渲染: 纹理上传、YUV→RGB、缩放 | wgpu | 集成测试 |
| `audio` | cpal 音频输出 + 主时钟来源 | cpal | 集成测试 |
| `subtitle` | 字幕解析 (.srt/.ass) 与渲染数据生成 | 无 | 纯逻辑,易单测 |
| `persist` | 偏好与播放记忆的本地文件存储 | serde | 纯逻辑,易单测 |
| `app` | egui UI + 组装所有 crate 的主程序 | 全部 | 手动验证 |

## 5. 功能范围 (首版)

### 核心播放
- 打开文件 (文件对话框 + 拖拽)
- 播放 / 暂停 / 停止
- seek (进度条拖动、点击)
- 音量调节 / 静音
- 全屏切换

### 播放列表
- 多文件队列管理
- 上一个 / 下一个
- 列表面板显示与切换

### 字幕支持
- 外挂字幕加载 (.srt / .ass)
- 内嵌字幕轨道切换
- 字幕渲染叠加

### 播放增强
- 倍速播放 (0.5x – 2x)
- 逐帧步进
- A-B 循环
- 截图

### 记忆播放状态
- 记住上次播放位置 (下次打开续播)
- 记住音量、窗口大小等偏好

## 6. 数据流 ("打开文件 → 播放")

1. 用户拖入文件 → UI 发 `OpenFile` 命令给 `player-core`
2. `player-core` 让 `media` 打开文件、读元数据 (时长/轨道/分辨率),广播状态给 UI(此时即可显示文件名/时长 → 秒开体感)
3. 解码线程启动,`media` 持续产出视频帧/音频帧 → 推入有界帧队列
4. `audio` 消费音频帧播放,同时推进主时钟
5. `sync` 根据主时钟决定每个视频帧"显示 / 丢弃 / 等待"
6. 到点的视频帧交给 `render` 上传 GPU 显示,叠加 `subtitle` 字幕
7. UI 每帧读 `player-core` 最新状态刷新进度条

## 7. 错误处理策略

播放器是消费级软件,任何错误都不应导致程序崩溃。最坏情况是"此文件放不了"并给出人话提示。

| 场景 | 处理 |
|------|------|
| 单帧解码失败 | 跳过该帧继续播放,不崩溃 |
| 整文件无法打开 | 友好提示("不支持的格式"/"文件损坏"),非技术堆栈 |
| 硬解失败 | 自动回退软解,对用户透明 (状态栏小字提示) |
| 音频设备拔出/切换 | 尝试重连,失败则静音继续放视频 |

## 8. 测试策略

- **单元测试**: `player-core` 状态机转换、`sync` 时钟对齐、`subtitle` 解析、`persist` 读写。
- **集成测试**: 准备数个小测试视频样本(不同格式/分辨率),测"打开→播放→seek→关闭"全流程不崩溃、帧数正确。
- **手动验证 (无法自动化,需三端真机)**: UI 交互体感、音画同步主观判断、各平台硬解实际效果、体积达标验证。
