# 计划 2.5: 硬件解码 (unsafe FFI 层) 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 `media` crate 中增加硬件解码支持(macOS VideoToolbox / Windows D3D11VA / Linux VAAPI),通过 `ffmpeg-sys-next` 的 unsafe FFI 实现,失败时透明回退软解码,对上层接口零侵入。

**Architecture:** 新增 `hwaccel` 模块,集中所有 unsafe FFI。`VideoDecoder::open` 改为 `open_with_options`,尝试为解码器附加硬件设备上下文 + `get_format` 回调;解码出的硬件帧用 `av_hwframe_transfer_data` 下载回内存,再走与软解相同的 sws→RGBA 路径。任何一步失败 → 回退纯软解。上层(engine/app)无需改动,只多一个"当前是否硬解"的状态供 UI 状态栏显示。

**Tech Stack:** ffmpeg-sys-next 8.1 (FFI), ffmpeg-next 8.1 (安全部分复用)。

**前置依赖:** 计划 2 已完成(软解管线可用,作为回退路径与共享代码)。

**风险声明:** 本计划包含大量 unsafe FFI,是整个项目最高风险部分。每个 unsafe 块必须带 `// SAFETY:` 注释说明不变量。硬解的正确性强依赖所链接 FFmpeg 的硬件支持编译选项与运行平台 GPU 驱动,**无法在所有环境自动测试**,需在三端真机人工验证。

- [ ] **Step 2: 实现设备上下文封装**

在 `hwaccel.rs` 中追加(测试模块之上)。`HwDeviceContext` 用 RAII 管理 FFI 资源:
```rust
use ffmpeg_sys_next as sys;
use std::ffi::CString;
use std::ptr;

/// RAII 包装一个 AVBufferRef* 硬件设备上下文。
pub struct HwDeviceContext {
    ptr: *mut sys::AVBufferRef,
    pub device_type: sys::AVHWDeviceType,
    pub hw_pix_fmt: sys::AVPixelFormat,
}

impl HwDeviceContext {
    /// 按平台名创建硬件设备上下文。失败返回 None(调用方回退软解)。
    pub fn create_for_current_platform() -> Option<Self> {
        let name = preferred_hw_name()?;
        let cname = CString::new(name).ok()?;

        // SAFETY: av_hwdevice_find_type_by_name 接受 C 字符串, 返回枚举值;
        // 无效名返回 AV_HWDEVICE_TYPE_NONE, 下面做了检查。
        let device_type = unsafe { sys::av_hwdevice_find_type_by_name(cname.as_ptr()) };
        if device_type == sys::AVHWDeviceType::AV_HWDEVICE_TYPE_NONE {
            return None;
        }

        let mut ptr: *mut sys::AVBufferRef = ptr::null_mut();
        // SAFETY: 传入合法的 out 指针与 device_type; 其余参数(设备名、选项)为 null,
        // 表示使用默认设备。返回值 < 0 表示失败, 此时 ptr 未被设置, 不需释放。
        let ret = unsafe {
            sys::av_hwdevice_ctx_create(
                &mut ptr,
                device_type,
                ptr::null(),
                ptr::null_mut(),
                0,
            )
        };
        if ret < 0 || ptr.is_null() {
            return None;
        }

        let hw_pix_fmt = hw_pix_fmt_for(device_type);
        Some(Self { ptr, device_type, hw_pix_fmt })
    }

    /// 暴露底层指针供 decoder 设置到 AVCodecContext。
    pub fn as_ptr(&self) -> *mut sys::AVBufferRef {
        self.ptr
    }
}

impl Drop for HwDeviceContext {
    fn drop(&mut self) {
        // SAFETY: ptr 由 av_hwdevice_ctx_create 成功创建; av_buffer_unref 接受
        // 指向该指针的指针并将其置空, 释放引用计数。仅在此处释放一次。
        unsafe { sys::av_buffer_unref(&mut self.ptr) };
    }
}

fn hw_pix_fmt_for(t: sys::AVHWDeviceType) -> sys::AVPixelFormat {
    use sys::AVHWDeviceType::*;
    use sys::AVPixelFormat::*;
    match t {
        AV_HWDEVICE_TYPE_VIDEOTOOLBOX => AV_PIX_FMT_VIDEOTOOLBOX,
        AV_HWDEVICE_TYPE_D3D11VA => AV_PIX_FMT_D3D11,
        AV_HWDEVICE_TYPE_VAAPI => AV_PIX_FMT_VAAPI,
        _ => AV_PIX_FMT_NONE,
    }
}
```

## Task 3: get_format 回调 + 帧下载 (unsafe FFI)

解码器需要一个 `get_format` 回调告诉 FFmpeg "我要硬件像素格式";解码出的硬件帧需用 `av_hwframe_transfer_data` 下载到普通内存帧。

**Files:**
- Modify: `crates/media/src/hwaccel.rs`

- [ ] **Step 1: 实现 get_format 回调**

在 `hwaccel.rs` 追加。回调通过 `AVCodecContext::opaque` 取回我们存入的目标硬件像素格式:
```rust
use std::os::raw::c_int;

/// 存入 AVCodecContext.opaque, 供 get_format 回调读取目标硬件格式。
pub struct HwCallbackData {
    pub hw_pix_fmt: sys::AVPixelFormat,
}

/// get_format 回调: 在候选格式列表中选我们的硬件格式; 找不到则回退首个(软)格式。
///
/// # Safety
/// 由 FFmpeg 在解码时调用。`ctx` 非空且其 `opaque` 指向有效的 HwCallbackData
/// (在 setup 时设置)。`fmt` 是以 AV_PIX_FMT_NONE 结尾的格式数组。
pub unsafe extern "C" fn get_hw_format(
    ctx: *mut sys::AVCodecContext,
    fmt: *const sys::AVPixelFormat,
) -> sys::AVPixelFormat {
    let data = (*ctx).opaque as *const HwCallbackData;
    if data.is_null() {
        return *fmt; // 无数据, 返回第一个候选
    }
    let want = (*data).hw_pix_fmt;

    let mut p = fmt;
    while *p != sys::AVPixelFormat::AV_PIX_FMT_NONE {
        if *p == want {
            return want;
        }
        p = p.add(1);
    }
    // 未找到硬件格式: 返回第一个候选(通常是软格式), 等效回退。
    *fmt
}

/// 把硬件帧下载到内存帧。成功返回 true。
///
/// # Safety
/// `hw_frame` 与 `sw_frame` 均为有效的 AVFrame 指针; hw_frame 持有硬件表面。
pub unsafe fn transfer_hw_frame(
    hw_frame: *mut sys::AVFrame,
    sw_frame: *mut sys::AVFrame,
) -> bool {
    // av_hwframe_transfer_data: dst, src, flags
    let ret = sys::av_hwframe_transfer_data(sw_frame, hw_frame, 0);
    if ret < 0 {
        return false;
    }
    // 拷贝 PTS 等元数据
    (*sw_frame).pts = (*hw_frame).pts;
    true
}
```

`decoder.rs`: 保留 `open` 作为便捷方法,核心逻辑进 `open_with_options`:
```rust
use crate::hwaccel::{DecodeOptions, HwCallbackData, HwDeviceContext};
use ffmpeg_sys_next as sys;

impl VideoDecoder {
    /// 默认尝试硬解(失败回退软解)。
    pub fn open(path: &Path) -> Result<Self, MediaError> {
        Self::open_with_options(path, DecodeOptions::default())
    }

    pub fn open_with_options(path: &Path, opts: DecodeOptions) -> Result<Self, MediaError> {
        ff::init()?;
        let ictx = ff::format::input(&path)?;
        let stream = ictx.streams().best(Type::Video).ok_or(MediaError::NoStream("video"))?;
        let stream_index = stream.index();
        let time_base = f64::from(stream.time_base());
        let ctx = ff::codec::context::Context::from_parameters(stream.parameters())?;
        let mut decoder = ctx.decoder().video()?;

        // 尝试附加硬件解码
        let mut is_hardware = false;
        let mut hw_device = None;
        let mut hw_cb_data = None;
        let mut hw_pix_fmt = sys::AVPixelFormat::AV_PIX_FMT_NONE;

        if opts.try_hardware {
            if let Some(dev) = HwDeviceContext::create_for_current_platform() {
                // SAFETY: decoder.as_mut_ptr() 返回有效 *mut AVCodecContext;
                // 我们设置 hw_device_ctx(av_buffer_ref 增引用)、get_format 回调、
                // opaque 指向 boxed HwCallbackData(其生命周期由 self 持有, 见下)。
                unsafe {
                    let avctx = decoder.as_mut_ptr();
                    let cb = Box::new(HwCallbackData { hw_pix_fmt: dev.hw_pix_fmt });
                    (*avctx).opaque = (&*cb as *const HwCallbackData) as *mut std::ffi::c_void;
                    (*avctx).hw_device_ctx = sys::av_buffer_ref(dev.as_ptr());
                    (*avctx).get_format = Some(crate::hwaccel::get_hw_format);
                    hw_pix_fmt = dev.hw_pix_fmt;
                    hw_cb_data = Some(cb);
                }
                hw_device = Some(dev);
                is_hardware = true;
            }
        }

        let (width, height) = (decoder.width(), decoder.height());
        // 软解 scaler: 源格式在硬解时为下载后的格式, 这里延迟到首帧确定。
        // 简化: 先按 decoder.format() 建; 若硬解, 首帧下载后格式可能不同, 见 scale 处理。
        let scaler = Scaler::get(
            decoder.format(), width, height,
            Pixel::RGBA, width, height, Flags::BILINEAR,
        ).ok();

        Ok(Self {
            ictx, decoder,
            scaler: scaler, // 注: 字段类型改为 Option<Scaler>, 见 Step 5
            stream_index, time_base, width, height, eof: false,
            is_hardware,
            _hw_device: hw_device,
            _hw_cb_data: hw_cb_data,
            hw_pix_fmt,
        })
    }

    pub fn is_hardware(&self) -> bool {
        self.is_hardware
    }
}
```

`decoder.rs` 的解码循环: 收到帧后判断是否硬件格式,是则下载到软件帧再 scale。修改 `next_frame` 中 `receive_frame` 成功分支:

新增辅助方法:
```rust
impl VideoDecoder {
    fn frame_is_hw(&self, frame: &FfVideo) -> bool {
        // SAFETY: frame 有效; 读取 format 字段。
        let fmt = unsafe { (*frame.as_ptr()).format };
        fmt == self.hw_pix_fmt as i32
    }

    fn download_and_scale(&mut self, hw: &FfVideo) -> Result<VideoFrame, MediaError> {
        let mut sw = FfVideo::empty();
        // SAFETY: hw 是有效硬件帧; sw 是空帧, transfer 会分配。
        let ok = unsafe { crate::hwaccel::transfer_hw_frame(hw.as_ptr() as *mut _, sw.as_mut_ptr()) };
        if !ok {
            return Err(MediaError::NoStream("hw transfer failed"));
        }
        let fmt = unsafe { std::mem::transmute::<i32, Pixel>((*sw.as_ptr()).format) };
        self.ensure_scaler(fmt)?;
        self.scale_software(&sw)
    }

    // 原计划 2 的 scale() 重命名为 scale_software, 接受任意软件帧:
    fn scale_software(&mut self, decoded: &FfVideo) -> Result<VideoFrame, MediaError> {
        let scaler = self.scaler.as_mut().expect("scaler 已构建");
        let mut rgba = FfVideo::empty();
        scaler.run(decoded, &mut rgba)?;
        let pts = decoded.pts().unwrap_or(0);
        let pts_ms = (pts as f64 * self.time_base * 1000.0).max(0.0) as u64;
        let stride = rgba.stride(0);
        let row_bytes = (self.width * 4) as usize;
        let src = rgba.data(0);
        let mut out = Vec::with_capacity(row_bytes * self.height as usize);
        for y in 0..self.height as usize {
            let start = y * stride;
            out.extend_from_slice(&src[start..start + row_bytes]);
        }
        Ok(VideoFrame::new(self.width, self.height, pts_ms, out))
    }
}
```

注: 删除/替换计划 2 中原 `scale` 方法为 `scale_software`。`transmute<i32, Pixel>` 依赖 `Pixel` 是 `#[repr(C)]` 的枚举(ffmpeg-next 的 `format::Pixel` 满足);更稳妥可用 `Pixel::from(raw)` 若该 API 存在——优先用 `Pixel::from((*sw.as_ptr()).format)`,实现时验证哪个可用。

## 已知风险与缺口

- **FFI 正确性**: `ffmpeg-sys-next` 的具体类型/枚举变体名以 8.1 实际导出为准,实现时需对照 `cargo doc`。本计划代码为骨架,FFI 细节(尤其枚举命名空间 `AVHWDeviceType::AV_HWDEVICE_TYPE_*`)需验证。
- **opaque 生命周期**: `HwCallbackData` 通过 `Box` 存活于 `VideoDecoder`,其裸指针存入 `avctx.opaque`。必须保证 decoder 存活期间 box 不移动/释放——已通过 `_hw_cb_data` 字段持有保证。
- **D3D11VA 帧下载**: Windows 上某些情况需额外处理纹理数组;若 `transfer_hw_frame` 在 Windows 失败率高,可能需 per-platform 特化(留待真机验证后决定)。
- **seek 与硬解**: seek 时解码器重建需重新走硬解 setup;在计划 4 实现 seek 时一并处理。
